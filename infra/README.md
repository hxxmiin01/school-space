# 인프라(Infrastructure as Code, IaC) 기초 폴더

> IaC(Infrastructure as Code, "서버·자원 설정을 코드로 적어두는 것")를 나중에 시작할 때
> 여기서부터 출발하면 됩니다. 이 폴더는 **아직 어떤 클라우드 도구를 쓸지 정하지 않은 상태**를
> 그대로 반영한 "중립 지대"입니다. 특정 리소스(가상 서버, DB 등)를 아직 만들지 않았습니다.

---

## 1. 이 폴더가 있는 이유

- `iac-foundation` 작업 항목은 원래 "Terraform 또는 Bicep을 골라서 앱·DB·메시징·AI·관측(observability)
  자원을 코드화하라"는 목표였습니다.
- 하지만 실제로 확인해보니, 그 목표에 필요한 몇 가지 결정이 **아직 안 끝났습니다** (아래 2절 참고).
- 결정이 안 끝난 상태에서 리소스를 미리 만들면, 나중에 실제 결정과 달라져서 다시 다 지우고
  새로 만들어야 할 수 있습니다. 그래서 지금은 **"틀"만 만들고, 실제 자원 코드는 비워둡니다.**

---

## 2. 지금까지 확정된 것 vs 아직 안 정해진 것

### 확정된 것 (여기서는 그대로 따릅니다)

| 항목 | 확정 내용 | 근거 |
| --- | --- | --- |
| 프론트엔드(화면) | React + Vite, Azure Static Web Apps에 수동 배포(az CLI) | `school-space-app/.azure/deployment-plan.md` |
| 데이터·로그인·사진·실시간 | Supabase (관리형 서비스라서 이 저장소의 IaC로 직접 만들 필요 없음) | `AGENTS.md` 2절, `deployment-plan.md` |
| 설문 | 구글 폼 (이 저장소 밖) | `AGENTS.md` 4절 |

→ Supabase는 "SaaS(다른 회사가 미리 만들어준 서비스를 빌려 쓰는 것)"라서, 이 폴더의 IaC 대상이
아닙니다. Static Web Apps는 이미 수동으로 만들어져 있고, 지금 당장 코드화가 급하지 않습니다.

### 아직 안 정해진 것 (그래서 실제 자원 코드를 못 씀)

| 항목 | 상태 | 관련 작업(todo) |
| --- | --- | --- |
| 백엔드 실행 환경(런타임) | "FastAPI든 다른 것이든 유연하게 유지"로 비교만 끝남, 특정 런타임 확정 안 됨 | `fastapi-backend-foundation` |
| 메시징(비동기 작업 전달 방식) | Service Bus / Event Hubs / 혼합 방식 비교만 끝남, 최종 선택 없음 | `message-bus-decision` |
| AI 기능(챗봇 등) | 아직 시작 전, Azure OpenAI 사용 여부·형태 미정 | `ai-assistant` |
| 관측(로그·지표·추적) 목적지 | Azure Monitor로 갈지 Grafana/Prometheus로 갈지 미정 | `observability-pipeline` |
| **이 폴더 자체의 도구 선택** | Terraform vs Bicep, 아직 미정 (3절 참고) | `iac-foundation` (이 문서) |

이 다섯 가지 중 하나라도 정해지지 않은 상태에서 실제 리소스를 코드로 쓰면, "추측으로 인프라를
만드는 것"이 됩니다. `AGENTS.md`의 규칙("정답이라고 단정하지 말고 이유를 같이 알려줄 것",
"PRD에 없는 걸 마음대로 추가하지 않을 것")에 따라, 지금은 자원 코드를 만들지 않습니다.

## 3. Terraform vs Bicep — 고르는 기준 (아직 선택 전)

| 도구 | 한 줄 설명 | 이럴 때 유리 |
| --- | --- | --- |
| **Terraform** | HashiCorp가 만든 범용 IaC 도구. 여러 클라우드(Azure, AWS, GCP 등)를 같은 문법으로 다룸 | 나중에 Azure 말고 다른 클라우드도 같이 쓸 가능성이 있을 때 |
| **Bicep** | Microsoft가 만든 Azure 전용 IaC 도구. ARM 템플릿보다 문법이 짧고 쉬움 | Azure만 계속 쓸 게 확실하고, Azure 공식 문서/지원을 더 중시할 때 |

- 지금까지 실제로 쓴 Azure 리소스는 Static Web Apps 하나뿐이라, 아직 "여러 클라우드를 섞어 쓸
  필요"가 있는지 판단할 근거가 부족합니다.
- **다음에 결정할 사람에게 물어볼 질문**: "Azure 하나만 계속 쓸 건가요, 아니면 다른 클라우드도
  고려하나요?" → Azure만 쓸 거면 Bicep, 여러 클라우드 가능성이 있으면 Terraform을 추천합니다.

## 4. 폴더 구조

```
infra/
├── README.md          # 이 문서
├── terraform/          # Terraform을 고르면 여기에 실제 코드 작성 (지금은 비어있음)
│   └── README.md
└── bicep/               # Bicep을 고르면 여기에 실제 코드 작성 (지금은 비어있음)
    └── README.md
```

도구가 정해지면, **선택하지 않은 쪽 폴더는 지우고** 선택한 쪽에만 실제 `.tf`/`.bicep` 파일을
채워 넣으면 됩니다. 두 폴더를 동시에 유지보수하지 않습니다.

## 5. 이 폴더를 다시 열어볼 때 체크리스트

1. 2절의 "아직 안 정해진 것" 표가 모두 채워졌는지 확인한다.
2. 3절의 질문에 답해서 Terraform/Bicep 중 하나를 고른다.
3. 고르지 않은 도구 폴더를 삭제한다.
4. 그제서야 실제 리소스(앱 호스팅, DB, 메시징, AI, 관측)를 코드로 작성한다.
